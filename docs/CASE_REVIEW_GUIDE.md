# 36题人工审定指南

## 审定目标

本轮审定不要求先运行模型。重点检查题目本身是否值得进入正式评测，以及题面、Gold、Rubric、工具环境和边界样例能否形成稳定合同。

每题给出一个决定：

- `保留`：结构成立，只需文字微调；
- `修改`：任务族成立，但题面、Gold或Rubric需要明显调整；
- `移除`：与研究问题重复、效度弱或难以稳定评分；
- `重做`：保留测量目标，重新设计完整Case。

## 通用检查

### 1. 来源与构念

- 题目测量的能力是否与所属Suite一致；
- 是否只是表面模仿公开任务；
- 是否可能与公开Benchmark原题或常见示例高度重合；
- 参考来源能否解释该题为什么被保留；
- 是否应该改入其他Track或Suite。

### 2. 题面

- 用户情境是否自然；
- 约束是否明确且互不冲突；
- 输出要求是否过长、过细或带有明显出题口吻；
- 是否存在多个合理理解；
- 是否无意泄露评分标准或参考解法；
- 难点来自任务本身，还是来自生硬措辞。

### 3. Gold

- 必须条件能否由题面直接推出；
- 可接受策略是否覆盖多类有效解；
- 禁止失败是否真的属于关键错误；
- 说明性样例是否被误写成唯一答案；
- 是否缺少现实世界中的常见有效方案；
- 是否存在物理、时间、数量或状态设定错误。

### 4. Rubric

- 每项是否自包含且可判；
- 0、1、2分锚点是否能区分明显失败、部分满足和充分满足；
- 是否把篇幅、术语或格式误当成创造性；
- 新颖性、适用性、约束、验证和过程是否被混为一项；
- 是否要求题面没有要求的内容；
- 自动检查与语义判断的边界是否合理。

### 5. 工具与Trace

- 工具是否提供任务真正需要的信息；
- 工具结果是否确定、可复现；
- 工具是否会无意提示正确答案；
- 工具错误、空结果和冲突结果是否覆盖；
- D类任务能否区分模型失败、工具失败、Harness失败和Judge失败；
- 达标停止是否有明确判据。

### 6. 边界样例

- `pass`是否真的满足关键约束；
- `fail`是否明确触发关键错误；
- `borderline`是否处于有意义的边界，而非随意写得较差；
- 三类样例是否覆盖不同失败机制；
- 样例是否过度贴合Gold，导致评分器只识别固定措辞。

## 各Suite优先关注

### A 心理学构念探针

- 不把人类量表解释直接套到模型；
- 分清语义远距、用途数量、机制多样性和情境适切性；
- A07—A09需要检查目标词与关系设置是否有效，避免只是词义知识题。

### B 约束创造问题解决

- 补齐材料属性、尺寸、重量、容量、摩擦、热交换等必要fixture；
- 检查有效方案是否被Gold遗漏；
- 确认不可行判断有明确物理依据。

### C 创造产品生成

- 场景、受众、交付格式和现实限制应足以支持实例化Rubric；
- 创意产物不能只按文风和长度评分；
- 叙事题应把状态一致性与文学偏好分开。

### D Loop适应与恢复

- 每题只突出一到两个主要干扰变量；
- Critic、记忆、工具和动态约束的错误来源需要分开记录；
- 终止判断应基于已满足的验收条件，不依赖模型自称完成。

## 审阅文件

CI会生成：

- `cases_full.md`：36题完整内容和逐题填写区；
- `cases_full.json`：机器可读完整数据；
- `review_sheet.csv`：汇总决策和修改意见；
- `provenance_summary.json`：来源审计摘要。

建议先在`review_sheet.csv`标记决定，再到`cases_full.md`记录具体修改。
