## 设计顺序

1. 先确定四类能力范围：心理学构念探针、约束创造问题解决、创造产品生成、Loop适应与恢复；
2. 再筛选公开方法和数据集，判断可采用、需改造、仅参考或排除；
3. 按每类9题设计题族；
4. 为每题补充工具环境、可接受解空间、禁止失败、Rubric和边界样例；
5. 建立离线运行、Trace、Oracle和回归测试。

## 最新公开研究带来的修正

2026年公开的CDAT与DRAT研究提示，人类创造力测验在LLM上的效度需要分构念判断，单一分数无法代表所有创造表现。AGC-Bench进一步说明，创造性评测覆盖多个领域，Judge偏差也需要校准。

这些研究支持当前项目继续采用多Suite、多维Rubric和Trace诊断，但不能证明当前36题已经具备同等效度。当前题集仍缺少：

- 人工逐题审定；
- 与公开基准的相似度和泄漏检查；
- 题面难度校准；
- Gold可接受解空间的人工扩充；
- Rubric评分者一致性；
- 不同任务族的权重与汇总规则验证。

## 建议的数据结构

后续建议把评测数据分为三个Track：

1. **Public replication**：按许可直接运行公开Benchmark，用于结果对照；
2. **Adapted parallel**：保留公开任务结构，替换情境、对象和约束，用于降低污染并做平行测试；
3. **Original diagnostic**：围绕工具、Critic、记忆、恢复和停止自建压力测试。

现有36题应暂时标为`adapted_parallel`或`original_diagnostic`，不应标为`public_replication`。

## 用户审定优先级

1. A类：确认心理学构念映射是否成立；
2. B类：确认物理条件、工具数据和可接受解是否完整；
3. C类：确认产物任务的现实场景、受众和语言要求；
4. D类：确认Loop干扰是否能区分模型问题、Harness问题和评测问题；
5. 逐题决定`保留 / 修改 / 移除 / 重新设计`。

完整题面、工具、Gold、Rubric和边界样例由CI导出到`review_pack` Artifact，供逐题修改。
