# 评测协议

## 运行单元

一次运行由 Case、模型配置、Loop配置、随机种子、工具fixture和评分版本共同确定。所有字段写入Trace。

## 结果分层

1. 执行状态：API、超时、工具和解析；
2. 硬约束：数量、格式、白名单、事实核；
3. 任务结果：方案或产品是否可用；
4. 构念维度：新颖性、适用性、多样性等；
5. Loop过程：验证、修订、恢复和停止；
6. 人工裁决：处理自动Judge分歧。

## Gold

开放任务采用可接受解空间。Gold包括必须满足的条件、允许的策略族、明确禁止的失败和一个说明性示例。示例不承担唯一答案作用。

## 首轮人工试做

每题至少由两名评分者独立完成：
- 题面可理解性；
- 是否存在无意的唯一答案；
- 工具信息是否足够；
- Rubric锚点是否能覆盖通过、边界和失败；
- 评分时间和分歧原因。

## 正式跑批建议

每个模型×Loop×Case至少重复3次。创造任务报告均值、离散程度、最差结果和关键失败概率，不要求文本逐字一致。
